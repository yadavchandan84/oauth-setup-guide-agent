# OAuth Guide Agent — full-build semantic review

The build delivers the whole OAuth App Approval Guide Agent described in requirements.md (ACs 1-25) and design.md revision 3: a shared zod schema with sync tooling and a link checker, a Node 22 + Express 4 agent API with an SSE research pipeline, 14 researched curated guides, a React 18 + Vite + R3F SPA, Vercel/Render deployment artifacts, and a puppeteer/marked submission PDF pipeline. I verified it by running the project's real build and test commands rather than trusting the FEAT reports: backend `tsc` build, 115 backend tests, frontend `tsc`+vite build, 38 frontend tests, the network link checker, the secret scan, and the draft PDF build. All passed. The three design-review findings and the NIT fixes are physically present in source, not just asserted in the FEAT notes.

Watch for: nothing blocking. The submission PDF is intentionally a **draft** because `submission/links.config.json` still holds `YOUR-...` placeholders for the live Vercel/Render URLs (confirmed — the build prints three placeholder warnings and exits 0). Per requirements A2 those URLs are user-supplied post-deploy; the final non-draft PDF cannot be produced until the user fills them in and redeploys. This is expected and out of the builder's control, not a defect.

**Verdict**: APPROVED

## High-level view

The schema is the single source of truth in `shared/schema.ts` and is copied into both apps by `scripts/sync-shared.mjs` before every build/test, so the frontend bundles the same curated data it validates against. Both apps compile against it with zero TypeScript errors, and the generated `curatedGuides.ts` is typed `GuideInput[]` so an invalid curated guide fails `tsc` in both packages.

The backend composes `/api/generate` as a deliberate middleware chain so only fresh pipeline runs consume rate-limit quota and slot acquisition stays atomic. Curated/cache hits short-circuit before config, slot, and limiter checks. The research pipeline (resolve → search → read → draft → verify → assemble → save) emits a typed SSE event stream, and the 115-test suite exercises the ordering, the 400/404/429/503 paths, CORS allow/deny, abort/timeout, and the index-99 / foreign-console-URL post-processing drops.

The three round-2 design-review findings are implemented and covered by tests: two-phase PDF token replacement (inline tokens escaped before marked, block HTML swapped after), draft/verifier normalization (`normalizeVerification`, empty-optional → undefined, verifier note only when it lowered the level, pipeline notes prepended before truncating `uncertain`), and a repair-retry flow that probes each draft with `assembleGuide(verification:null)`, repairs at most once, runs verification exactly once, and emits `LLM_FAILED` on a second failure.

The security posture is sound for the scope: no API keys are required to boot and serve the curated library, generation returns `503 CONFIG_MISSING` without them, the server never fetches user-supplied URLs (Tavily does), helmet is on, CORS is exact-match against an allow-list, and the secret scan finds nothing key-shaped in the repo.

The frontend keeps the landing bundle well under the 250 KB gzip budget (index 70.85 KB gz + Landing 3.01 KB gz) and splits the 3D hero into a separate 248 KB-gz lazy chunk that never loads in fallback mode. The curated library is bundled, so it works with the API unreachable.

The submission PDF builds to 1.68 MB (< 10 MB) with all FR12 sections, an inline SVG diagram, three real sample excerpts, seven embedded screenshots, and the Loom-absence guard passing. It is a draft only because the live URLs are still placeholders.

### Design-review findings land in source, not just in notes

I confirmed each finding by reading the implementing code rather than relying on the FEAT claims.

Finding #1 (two-phase PDF replacement) is in `submission/build-pdf.mjs`: `BLOCK_TOKEN_NAMES = ['ARCHITECTURE_SVG','SAMPLE_GUIDES','LINK_CHECK_TABLE','SCREENSHOTS']` are explicitly skipped in phase 1 (`replaceInlineTokens` returns the match unchanged for block keys and HTML-escapes inline config tokens), then swapped as raw HTML into the `<p>{{KEY}}</p>` wrappers after marked runs. This is the exact fix for the escaped-`<pre><code>` bug the review flagged, and the build guards fail loudly on any leftover `{{...}}` token or escaped `&lt;svg`/`&lt;table`/`&lt;figure`.

Finding #2 (normalization) is in `postprocess.ts`: `normalizeVerification` trims fields, drops empty array items, and maps empty notes to `undefined`; `assembleGuide` calls it only when a verification object exists (`rawVerification ? normalizeVerification(rawVerification) : null`), so the probe path with `verification:null` is unaffected. `normalizeDraft` handles the empty-optional-string → undefined rule that zod's `Str().optional()` otherwise rejects.

Finding #3 (repair-retry) is in `pipeline.ts`: after each `deps.draft({ ..., repairIssues }, signal)` the code runs `assembleProbe` which calls `assembleGuide({ draft, verification: null, ... })`; on `DraftInvalid` it sets `repairIssues = err.issues.slice(0,10)` and re-emits the `draft` step as active with a "Repairing an invalid draft…" detail, but the `attempts` guard caps this at one repair and a second failure throws `AgentError('LLM_FAILED', …)`. Verification runs once, after the draft loop. `DraftInvalid` is exported from `llm.ts` and caught by `instanceof`, so it never escapes `runPipeline`.

### SSE pipeline and the middleware chain

The `/api/generate` chain orders body-parse → `validateBody` → `shortCircuit` → `requireConfig` → `acquireSlot` → `limiter` → `runGeneration`, so a curated/cache hit never reaches the limiter and a `BUSY` rejection never burns rate-limit quota. The route owns `meta`/`done`/`error`; the pipeline emits only `step`/`source`/`guide`. `routes.test.ts` (21 tests) covers the `meta → step → guide → done` ordering with a schema-valid guide, the 400 `INVALID_INPUT` input cases plus `"  Asana  "` accepted, `503 CONFIG_MISSING`, the 429-after-limit path with `Retry-After` where cached/curated hits don't count, CORS allow/deny, and the cached-second-request `cached:true` without re-running the pipeline. `pipeline.test.ts` (14 tests) covers verifier-fail-still-yields-a-guide, `NO_SOURCES`, `TIMEOUT`, abort-stops-further-calls, and the index-99 / foreign-console-URL drops.

### Security and config posture

The server boots without `OPENAI_API_KEY`/`TAVILY_API_KEY`; `requireConfig` returns `503 CONFIG_MISSING` and `server.ts` wires stub LLM/search deps that throw `CONFIG_MISSING` so a keyless `/api/generate` streams a clean error instead of crashing. User-supplied URLs are only used as a Tavily search hint, never fetched by our server, so there's no SSRF surface. CORS is exact-match against `ALLOWED_ORIGINS` with no ACAO header for disallowed origins. Helmet is enabled with cross-origin resource policy. The secret scan is clean and `.gitignore` tracks `.env.example` while ignoring every other `.env*` and the generated dirs.

### Curated content honesty

`curated.test.ts` (6 tests) enforces 14 schema-valid guides with unique slugs, ≥2 sources each with ≥1 official, all-https URLs, valid `lastVerified` dates, actors in {agent,human,assist}, all four difficulty levels present, and the fixed GitHub=Easy / Google=Very Hard / Shopify=Hard pins. The FEAT-003 notes record Figma's review question as resolved to `required:true` against the official oauth-apps page (confidence `verified`), with approval-wait durations kept `community` where no official figure exists — consistent with the "honesty over polish" rule.

### Frontend graceful degradation

`Hero.test.tsx` confirms that with reduced-motion or no-WebGL no `<canvas>` renders and the SVG fallback appears; the build output confirms the 3D chunk is separate and not pulled into the landing path. `GuideView.test.tsx` asserts exactly nine `confidence-*` testids (one per `SECTION_KEYS`, none on summary/sources) and the "Link copied" toast. `GuideDetail.test.tsx` confirms both 400 and 404 render "Guide not found" with no Retry (AC 20b). `Generate.test.tsx` covers steps rendering as they arrive, the error panel with Try again, cancel aborting, the 4s cold-start notice hiding on first byte, and the `llmConfigured:false` banner with the input still enabled.
